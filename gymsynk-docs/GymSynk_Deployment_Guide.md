**Standalone Deployment**

GymSynk operates as a completely standalone Docker Compose stack. It runs its own Traefik container to handle TLS certificate provisioning and reverse proxy routing, ensuring no port or network conflicts with other applications on the host.

# 2\. Quick Start

## Step 1 - Clone

git clone <https://github.com/trillionclues/gymsynk.git>

cd gymsynk

## Step 2 - Run the Setup Script

The setup-cli.sh script handles everything: generates secrets, writes .env, starts containers, and opens your browser to the setup wizard.

chmod +x setup-cli.sh

./setup-cli.sh

The script will prompt for:

- Your domain (e.g. gym.acmegym.com)
- ACME email for Let's Encrypt TLS certificate
- Payment mode (CASH_ONLY / TRACK_AND_RECEIPT / FULL_PROCESSING)
- LemonSqueezy or Paystack secret key (only if FULL_PROCESSING selected)

It auto-generates: POSTGRES_PASSWORD, REDIS_PASSWORD, JWT_SECRET (32-byte random hex).

> **Note:** SMS OTP delivery is not available in v1. Member authentication uses email OTP only (via Resend/SMTP). SMS support (Termii/Twilio) is planned for v1.5.

## Step 3 - Complete the Web Setup Wizard

Once containers are healthy, your browser opens to <https://DOMAIN/setup>. Complete the 6-step wizard:

- Gym name, logo, timezone, currency
- Location name and address
- Operating hours - which days, morning/evening times
- Payment mode confirmation
- Initial plans - pre-filled with Daily/Weekly/Monthly templates, edit prices as needed
- Admin account - email and password

After Step 6, setup_complete is set to true and the wizard is permanently disabled. You are redirected to the cashier login.

## Step 4 - Verify

- Visit <https://DOMAIN> - cashier login page loads
- Login with admin credentials from Step 6
- Register a test member → assign a plan → generate their QR
- Open the member PWA on a phone - login via OTP → tap Check In → QR appears
- Scan the QR from the cashier portal → green confirmation on member screen, check-in appears in dashboard live feed

# 4\. Docker Compose Structure

The production docker-compose.yml spins up 5 containers. All internal communication is over a standalone bridge network. Only Traefik exposes ports 80 and 443 publicly to route traffic based on Host headers and auto-provisions TLS certs.

```yaml
services:
  api:
    build: ./backend
    environment:
      SPRING_PROFILES_ACTIVE: prod
      DB_URL: jdbc:postgresql://db:5432/gymsynk
      DB_PASSWORD: ${POSTGRES_PASSWORD}
      REDIS_HOST: redis
      REDIS_PASSWORD: ${REDIS_PASSWORD}
      JWT_SECRET: ${JWT_SECRET}
      SMTP_HOST: ${SMTP_HOST:-smtp.resend.com}
      SMTP_PORT: ${SMTP_PORT:-465}
      SMTP_USERNAME: ${SMTP_USERNAME:-resend}
      SMTP_PASSWORD: ${SMTP_PASSWORD}
      FRONTEND_URL: ${FRONTEND_URL:-https://${DOMAIN}}
      JAVA_OPTS: "-Xms256m -Xmx512m -XX:+UseZGC -XX:+ZGenerational"
    depends_on:
      db: { condition: service_healthy }
      redis: { condition: service_healthy }
    restart: unless-stopped
    labels:
      - traefik.enable=true
      - traefik.http.routers.gymsynk-api.rule=Host(`${DOMAIN}`) && PathPrefix(`/api`)
      - traefik.http.routers.gymsynk-api.entrypoints=websecure
      - traefik.http.routers.gymsynk-api.tls.certresolver=letsencrypt
      - traefik.http.services.gymsynk-api.loadbalancer.server.port=8080

  web:
    build: ./frontend
    environment:
      NEXT_PUBLIC_API_URL: https://${DOMAIN}/api
    restart: unless-stopped
    labels:
      - traefik.enable=true
      - traefik.http.routers.gymsynk-web.rule=Host(`${DOMAIN}`)
      - traefik.http.routers.gymsynk-web.entrypoints=websecure
      - traefik.http.routers.gymsynk-web.tls.certresolver=letsencrypt
      - traefik.http.services.gymsynk-web.loadbalancer.server.port=3000

  db:
    image: postgres:16-alpine
    command: postgres -c shared_buffers=128MB -c max_connections=50 -c work_mem=4MB
    volumes:
      - pgdata:/var/lib/postgresql/data
    environment:
      POSTGRES_DB: gymsynk
      POSTGRES_USER: gymsynk
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U gymsynk"]
      interval: 5s
      retries: 5
    restart: unless-stopped

  redis:
    image: redis:7-alpine
    command: redis-server --requirepass ${REDIS_PASSWORD} --appendonly yes --maxmemory 64mb --maxmemory-policy allkeys-lru
    volumes:
      - redisdata:/data
    healthcheck:
      test: ["CMD", "redis-cli", "-a", "${REDIS_PASSWORD}", "ping"]
      interval: 5s
      retries: 5
    restart: unless-stopped

  traefik:
    image: traefik:v3
    command:
      - --providers.docker=true
      - --providers.docker.exposedbydefault=false
      - --entrypoints.web.address=:80
      - --entrypoints.websecure.address=:443
      - --entrypoints.web.http.redirections.entrypoint.to=websecure
      - --entrypoints.web.http.redirections.entrypoint.scheme=https
      - --certificatesresolvers.letsencrypt.acme.email=${ACME_EMAIL}
      - --certificatesresolvers.letsencrypt.acme.storage=/certs/acme.json
      - --certificatesresolvers.letsencrypt.acme.httpchallenge.entrypoint=web
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock:ro
      - traefik-certs:/certs
    restart: unless-stopped

volumes:
  pgdata:
  redisdata:
  traefik-certs:
```

# 5\. Updates

git pull origin main

docker compose pull

docker compose up -d --build

If the update includes schema changes (check CHANGELOG.md), Flyway runs migrations automatically on API startup. Migrations are always additive (no column drops) within a minor version. Breaking migrations are gated behind major version bumps with explicit operator instructions.

**Zero-Downtime Updates**

Traefik's health check integration means the old container continues serving traffic until the new one passes its /api/v1/actuator/health check. For a single-VPS deployment this is effectively zero-downtime. For true zero-downtime with database migrations, follow the expand-contract pattern documented in /docs/migrations.md.

# 6\. Backups

## Database

docker exec gymsynk-db pg_dump -U gymsynk gymsynk > backup_$(date +%Y%m%d_%H%M).sql

Schedule via cron - daily at 2 AM:

0 2 \* \* \* docker exec gymsynk-db pg_dump -U gymsynk gymsynk | gzip > /backups/db_$(date +%Y%m%d).sql.gz

## Redis

Redis AOF persistence is enabled by default (--appendonly yes). The /data volume is mounted - data survives container restarts. For full backup, copy the /data volume contents:

docker exec gymsynk-redis redis-cli BGSAVE

docker cp gymsynk-redis:/data/dump.rdb ./redis-backup-$(date +%Y%m%d).rdb

> **Note:** There is no file uploads volume to back up. GymSynk stores no files on disk — avatars are generated client-side, receipts are streamed on-demand. All persistent data is in PostgreSQL and Redis.

# 7\. Security Hardening Checklist

| **Action**                     | **Command / Location**                                       | **Priority**                             |
| ------------------------------ | ------------------------------------------------------------ | ---------------------------------------- |
| Change all default passwords   | Set via setup-cli.sh - auto-generated                        | Critical - before first deploy           |
| UFW firewall on VPS            | ufw allow 22; ufw allow 80; ufw allow 443; ufw enable        | High                                     |
| Fail2ban on SSH                | apt install fail2ban - default config blocks brute force     | High                                     |
| Rotate JWT_SECRET periodically | Update .env, docker compose up -d - invalidates all sessions | Medium - quarterly                       |
| Review audit_log monthly       | Admin portal → Audit Log → filter by last 30 days            | Medium                                   |
| Set POSTGRES_MAX_CONNECTIONS   | In docker-compose.yml db command: -c max_connections=50      | Low - default 100 is fine for single gym |
| Enable 2FA for admin accounts  | Available in v1.1 - note in admin settings once shipped      | v1.1 |                                    |

# 8\. Monitoring

| **What**             | **Tool**                                                                           | **Alert Threshold**                                |
| -------------------- | ---------------------------------------------------------------------------------- | -------------------------------------------------- |
| API health           | GET <https://DOMAIN/api/v1/actuator/health> via UptimeRobot (free tier)            | Non-200 response                                   |
| Disk usage           | VPS provider dashboard or df -h cron alert                                         | 70% - Local uploads and DB grow over time          |
| Container restarts   | docker compose ps - check Restarting status                                        | Any unexpected restart                             |
| Postgres connections | docker exec gymsynk-db psql -U gymsynk -c 'SELECT count(\*) FROM pg_stat_activity' | \> 40 (if max_connections=50)                      |
| Redis memory         | docker exec gymsynk-redis redis-cli INFO memory                                    | \> 80% of maxmemory (if set)                       |
| Failed check-ins     | Admin portal → Check-In Log → filter by status=EXPIRED_PLAN for last 7 days        | Sudden spike = plan config issue or renewal needed |

# 9\. Nginx Alternative

Traefik is the recommended reverse proxy for its simplicity and automatic TLS. If you prefer Nginx, a reference config is provided at /docs/nginx.conf. Key differences:

- Manual TLS cert management required (Certbot: certbot --nginx -d DOMAIN)
- WebSocket upgrade headers must be explicitly configured (proxy_http_version 1.1; proxy_set_header Upgrade; proxy_set_header Connection 'upgrade')
- No automatic container discovery - Nginx config must be updated manually on new deployments
- Rate limiting configured in Nginx location blocks rather than Traefik middleware

For operators already running Nginx, the /docs/nginx.conf reference handles all of the above with annotated comments.

# 10\. Troubleshooting

| **Symptom**                       | **Likely Cause**                                                | **Fix**                                                                                                     |
| --------------------------------- | --------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| API container restarts on startup | DB not ready - healthcheck race                                 | Check db healthcheck passes before api starts. Review depends_on condition.                                 |
| WebSocket not connecting          | CORS or proxy misconfiguration                                  | Confirm Traefik WebSocket middleware is configured. Check NEXT_PUBLIC_API_URL matches domain.               |
| QR scan returns TOKEN_EXPIRED     | Redis TTL too short for slow networks or busy cashiers          | Increase qr.token.ttl-seconds in application-prod.yml. Default 120s.                                        |
| OTP email not arriving        | Wrong SMTP config or unverified From address        | Check SMTP provider delivery logs. Verify SMTP_FROM is a domain verified with your SMTP provider. For Resend, ensure your domain is verified in the Resend dashboard.   |
| Flyway migration failed           | SQL syntax error or version conflict                            | Check docker compose logs api for Flyway error. Fix migration file (never edit already-applied migrations). |
| check_ins table too slow          | Missing index or table not partitioned                          | Run EXPLAIN ANALYZE on the slow query. Partitioning guide: /docs/partitioning.md.                           |
